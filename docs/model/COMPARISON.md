# Model comparison and promotion decision

_Generated by `curator model compare` from `artifacts/evals/`. Do not edit by hand._

Every rung was trained on the label sets shown in the table (`train`: the first training sample; `train_2`: the second sample, plan section 3.2), tuned and calibrated on gold-dev (the `v1-*-v1-thresholds` rows keep v1's shipped thresholds; only their calibration is fitted on gold-dev), and scored once on gold-test (1,200 reviews from 182 hotels the models never saw). Intervals are 95% hotel-cluster bootstrap intervals; "test minus v1" is a paired bootstrap against v1's best configuration on gold-dev (`v1-parts-dev-thresholds`). Rules are those of the plan, §3.6, applied together: 1 beats v1, with the paired interval above 0; 2 among the rungs passing 1, the best gold-dev macro-F1 is the candidate (ties within 0.01 go to the smaller model); the candidate ships only if it also passes 3, mean review-level ECE <= 0.05, and 4, scoring the corpus in under 4 hours. Rule 4 is measured on the packaged ONNX model (`curator model package`); P re-checks rules 1 and 3 on that package's own gold-test scores, since the package is what is served. `-` in the rules column means not measured.

**Decision: promote `roberta-base-ft-train2`.**

## Run notes

- `electra-small-ft`: Trained with batches drawn at random. Length-bucketed batching (batches of similar-length parts, in shuffled order; `ml/encoder.py::length_bucketed_batches`) was added after this run and used for every later encoder. Bucketing changes the batch composition and the CPU time, not the hyperparameters, which are fixed in advance (plan section 3.6). The run was not repeated, so its training time is not directly comparable with the other encoders.
