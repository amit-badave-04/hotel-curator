# Data card: hotel-curator v2

What data the product is built on, where it comes from, what it contains,
what was done to it, and what it should and should not be used for. Numbers
come from `data/manifests/data.json` and `docs/data/EDA.md`, both generated by
code (`make data`, `make eda`).

## 1. Source

| | |
|---|---|
| Name | 515K Hotel Reviews Data in Europe |
| Original publisher | Kaggle user `jiashenliu`, scraped from Booking.com |
| Original URL | https://www.kaggle.com/datasets/jiashenliu/515k-hotel-reviews-data-in-europe |
| Copy used | GitHub `raghavendranhp/Dynamic-Hotel-Recommendation-System-Using-NLP`, commit `903600f2`, folder `Datas/`, 11 CSV chunks |
| Integrity | SHA-256 of each chunk pinned in `hotel_curator.data.sources`; the re-assembled table must have exactly the documented 515,738 rows and 17 columns; a parse-level content fingerprint is recorded in the manifest |
| Licence | CC0 1.0 as declared by the uploader; content originally owned by Booking.com; not confirmed first-hand (Kaggle is blocked from the build machine) |
| Why this source | Only reachable candidate with real hotel identity, coordinates, dates, Liked/Disliked parts and traveler tags (ADR 001) |

## 2. What is in it

| Fact | Value |
|---|---|
| Raw rows | 515,738 |
| Exact duplicate rows dropped | 526 |
| Reviews kept | 515,212 |
| Hotels (name + address) | 1,494 |
| Cities | Amsterdam (105 hotels), Barcelona (211), London (400), Milan (162), Paris (458), Vienna (158) |
| Period | 2015-08-04 to 2017-08-03 |
| Reviews per hotel | min 8, median 194, max 4,789 |
| Liked part missing (site placeholder "No Positive") | 7.0% of reviews |
| Disliked part missing (site placeholder "No Negative") | 25.0% of reviews |
| Reviews with no text at all | 236 |
| Hotels without coordinates | 17 |
| Traveler types | couple 48.9%, solo 21.0%, group 12.7%, family with young children 11.8%, family with older children 5.1%, friends 0.4% |
| Trip types | leisure 81.0%, business 16.1%, unknown 2.9% |
| Language | English (99.6% of a 20,000-review sample, measured with py3langid during research) |

Columns used by v2 (canonical tables, contract in
`hotel_curator.data.contracts`):

- **hotels**: `hotel_id`, `name`, `address`, `city`, `country`, `lat`, `lng`,
  `source_average_score` (the site's own average, a single snapshot),
  `source_total_reviews`, `n_reviews`, `split`.
- **reviews**: `review_id`, `hotel_id`, `review_date`, `reviewer_nationality`,
  `reviewer_score`, `reviewer_review_count`, `liked_text`, `disliked_text`,
  `trip_type`, `traveler_type`, `room_type`, `nights`, `with_pet`,
  `from_mobile`, `split`.

## 3. Known quirks

| Quirk | Handling |
|---|---|
| **Punctuation was removed by the publisher** (no periods, commas, apostrophes: "Earl s Court", "didn t"); case is kept | Text is used as is. The same normalisation is applied to API input so the model never sees a different alphabet in production. Evidence is shown verbatim with a note. |
| Leading spaces in most text fields | Whitespace is collapsed. |
| "No Positive" / "No Negative" are site placeholders | Mapped to a missing part. |
| Guest-written content-free parts ("Nothing", "None", "N A") | Kept verbatim; the classifier and annotators give them no labels. |
| Same property under two names at one address (one case) | Both kept as hotels; forced into the same split. |
| "Hotel Regina" in three cities | Three different hotels (different addresses). |
| `days_since_review` is relative to the scrape date | Not used; `review_date` is used instead. |
| `Average_Score` and `Total_Number_of_Reviews` are a single snapshot per hotel | Used only as an external validation signal, never as a model input. |

## 4. Splits

Hotel-disjoint, stratified by city and review-count band, seeded and
independent of row order (`hotel_curator.data.split`):
**1,048 train / 220 val / 226 test hotels** (355,302 / 81,171 / 78,739 reviews
before the same-address adjustment; exact current numbers in the manifest).
No hotel appears in two splits.

## 5. Labels

See [`docs/labeling/GUIDELINES.md`](../labeling/GUIDELINES.md) and ADR 004.
Gold-test comes only from test hotels, gold-dev only from validation hotels,
training labels only from train hotels. Labels are produced by an LLM
annotator panel and are **not human ground truth**.

## 6. Personal data

- No reviewer names or ids are present in the source.
- `reviewer_nationality` is present; the product shows it only in aggregates,
  never next to a review's date, room type and nights.
- Review text can name staff ("thanks to Maria at reception"). Displayed
  excerpts are length-capped and person names are redacted before display.
- No attempt is made to identify reviewers.

## 7. Intended and out-of-scope uses

- **Intended**: research and demonstration of attribute-level hotel quality
  analysis for the six cities and the 2015-2017 period.
- **Out of scope**: claims about these hotels' *current* quality; commercial
  use without a legal review of the source licence; any reviewer-level
  profiling.

## 8. Rebuild

```
make data      # downloads ~240 MB, verifies 11 digests, builds and validates (about 1 minute)
make eda       # regenerates docs/data/EDA.md and the figures
```

Compare the new `data/manifests/data.json` with the committed one: equal
digests mean identical data.
